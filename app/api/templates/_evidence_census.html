Key — what each one means
{{ census.clean }} clean

Enough history for both buying and selling, no missing sessions, every scan reading the strategies ask for present.

Only these can produce a Buy. A Hold here is the strategy's opinion, not a data problem. The FX ceiling on the Strategy data tab still applies.

{% if 'thin' in census.fault_counts %}
{{ census.fault_counts['thin'] }} thin

Fewer sessions than a declared minimum. Buying usually needs more history than selling, so a security can pass one path and fail the other.

It drops out of whichever path it fails and the recommendations screen will not say so. That is why this table splits entry from exit.

{% endif %} {% if 'gapped' in census.fault_counts %}
{{ census.fault_counts['gapped'] }} gapped

Enough trading days on paper, but sessions are missing out of the middle of the window.

The dangerous one. A 200-session average missing 8 sessions really reaches back 208. It still calculates, so Stage and VCP come out wrong with no error anywhere.

{% endif %} {% if 'missing_fragment' in census.fault_counts %}
{{ census.fault_counts['missing_fragment'] }} missing fragment

Price history is fine, something else is not: the history could not be read, or a detector failed.

More history will not help. The strategy asked for a reading the scan never produced.

{% endif %} {% if 'dropped' in census.fault_counts %}
{{ census.fault_counts['dropped'] }} dropped

Never got in at all. A stale session, an ambiguous ticker, colliding identities, or no prices.

Recommendations cannot see these. Hold one and it is forced to Hold; do not and it never comes up. These are the losses the funnel above can explain.

No new storage. Sessions, evidence kinds, session range and missing sessions come from evidence_coverage on the published scan view. Drop reasons come from the artifact's own current evidence gaps and from unresolved identities. Expected trading days come from the pinned calendar. The FX ceiling comes from fx:GBPUSD=X. Entry and exit thresholds come from each Strategy's declared evidence_requirements. Discovery totals come from SourceHealth.count on this run's log row.

Two kinds of requirement. A Strategy asks for price history and scan readings per security, with separate minimums for entry and exit. FX, the calendar and the benchmark are not on that list; they are fixed per run. So a Strategy can be stopped by something it has no way to ask for.
