## Intent

**Problem:** Reopening Configure a Backtest discards the settings from the user's previous completed run, making normal iteration repetitive.

**Approach:** Safely project the most recent completed result's immutable run configuration onto the current configuration form, using only current discoverability and Ready coverage, with a clear reset to the first-run defaults.

## Boundaries & Constraints

**Always:** Source recall from a completed, validated `BacktestResultV1`, newest-first; retain current profile hash, activation sequence, idempotency key, discovery schema, roster and launch validation. Keep persisted values only when they remain valid in the current UI contract. Degrade to safe defaults with a concise notice when recall cannot be used.

**Block If:** The repository cannot reliably identify the most recent completed result without relying on non-durable activity metadata.

**Never:** Reuse an old idempotency key, profile/activation identity, preparation evidence, stale strategy descriptor, or deleted/unvalidated universe member. Do not prefill from queued, running, failed, cancelled, or tombstoned activities.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Completed history | Latest valid completed backtest result | Form recalls its strategy, current compatible parameters, period, capital and currency | Fresh launch identity remains generated by the current form |
| No completed history | No eligible result | Existing first-run defaults | No notice required |
| Unavailable strategy | Recalled strategy absent from discovery | No strategy selected; compatible non-strategy values remain where safe | Inform the user that the strategy is unavailable |
| Invalid recalled period | Range is outside one current Ready interval | Normal blank period defaults | Explain that a new ready period is needed |
| Reset | User selects Reset to defaults | Full configuration response uses first-run defaults | No stale recalled values remain |

</intent-contract>

- Given the remembered strategy is no longer discoverable, when the form opens, then no strategy is selected while safe non-strategy defaults remain available.
- Given recalled settings, when Reset to defaults is used, then the normal first-run form returns with no recalled values.
- Given no previous completed result, when the form opens, then it behaves as the existing first-run form.
- Given a recalled form, when submitted, then the existing validation and one-launch guarantee remain authoritative.

## Design Notes

“Most recent” means the newest completed immutable result, not the newest activity, because recent failed or queued jobs do not supply a full, trustworthy configuration. A historic V2 selected-security snapshot belongs to an older profile and is not reused as a live universe: the form defaults to the current whole universe. This intentionally prioritises current roster/coverage safety over an exact replay shortcut.
