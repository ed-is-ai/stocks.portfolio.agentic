## Why this matters

The project's own `.claude/CLAUDE.md` is emphatic: "ONLY use uv, NEVER pip … uv
add package". The README's setup section uses `uv run`/`uv add`. But there is **no
`pyproject.toml` and no `uv.lock`** — only an unpinned `requirements.txt` with
`>=` constraints. Consequences today: installs are non-reproducible (any future
release of pandas/yfinance/pydantic can silently change behavior of a financial
tool), there's no single source of truth for the toolchain, and the scanner has
to paper over the gap with a **hardcoded Windows `uv.exe` path**. This plan makes
the repo match its declared standard: a `pyproject.toml` describing the project, a
committed `uv.lock` for reproducible installs, and removal of the hardcoded path.

### Step 2: Write `pyproject.toml`

Create `pyproject.toml` at repo root. Use the current pinned-floor versions from
`requirements.txt` as lower bounds; let `uv lock` pick exact versions. Template:

```toml
[project]
name = "agents-stocks"
version = "0.1.0"
description = "Multi-agent stock portfolio management (CANSLIM + Weinstein Stage analysis)"
readme = "README.md"
requires-python = ">=3.12"
dependencies = [
    "pydantic>=2.0.0",
    "yfinance>=0.2.40",
    "pandas>=2.0.0",
    "openai>=1.30.0",
    "apscheduler>=3.10.0",
    "requests>=2.31.0",
    "openpyxl>=3.1.0",
    "playwright>=1.44.0",
    "python-dotenv>=1.0.0",
    "fastapi>=0.110.0",
    "uvicorn>=0.29.0",
    "jinja2>=3.1.0",
    # add "pandas-ta>=0.3.14b" only if Step 1 shows it is still imported
]

[dependency-groups]
dev = [
    "pytest>=7.0.0",
    "pytest-asyncio>=0.21.0",
    "pytest-json-report>=1.5.0",  # pytest.ini addopts use --json-report
]

[tool.uv]
# (left default; uv reads [dependency-groups] for dev deps)
```

Notes:
- `requires-python = ">=3.12"` is a safe floor (the repo runs on 3.14 locally and
  uses `from __future__ import annotations` / `X | None` syntax). Do NOT pin to a
  single version.
- Use `[dependency-groups]` (the modern uv/PEP 735 location) for dev tools, so
  `uv sync` installs them and `uv sync --no-dev` skips them.
- Keep `pytest.ini` as the pytest config; `pyproject.toml` only declares the dep.

### Step 3: Generate and commit the lockfile

```bash
uv lock
uv sync
```

`uv lock` writes `uv.lock`. Ensure it is **tracked** (not gitignored):

```bash
grep -nE "uv\.lock" .gitignore || echo "uv.lock not ignored — good"
```

If `.gitignore` ignores it, remove that line.

**Verify**: `git status` shows `pyproject.toml` and `uv.lock` as new files;
`uv sync` exits 0.

### Step 4: Remove the hardcoded uv path in the scanner

With uv as a declared tool, the Windows-specific fallback is no longer
appropriate. In `agents/scanner/scanner_agent.py:114` change:

```python
uv = shutil.which("uv") or str(Path.home() / "AppData/Roaming/Python/Python314/Scripts/uv.exe")
```

to:

```python
uv = shutil.which("uv")
if not uv:
    print("  [skip] vcp_screener: uv not found on PATH")
    return []
```

(Place the early-return before the `tempfile.TemporaryDirectory()` block. This
fails cleanly and portably instead of pointing at one user's machine.)

**Verify**: `grep -n "AppData/Roaming" agents/scanner/scanner_agent.py` → no
matches.
